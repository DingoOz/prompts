GOAL: Build a complete, playable, visually stunning vertical shoot ’em up in the spirit of Sky Force Reloaded. Ship a polished single-player native desktop game, run locally on the operating system available (e.g. Ubuntu), that feels AAA: dense particle FX, screen shake, bloom, heat distortion, layered parallax, satisfying hit-stop, and a cinematic audio mix. Generate all art, VFX, UI, and audio yourself. Do not leave placeholder boxes or beep sounds.

TITLE (working): STELLAR REVENANT

PILLARS
- Vertical scrolling shooter. Camera always travels upward through a long map. Player stays in the lower third of the screen.
- Auto-fire primary weapon. The ship fires continuously with no button held. Player only steers and triggers secondaries.
- Dual input: Xbox / generic gamepad (via the chosen library's controller API) + full keyboard. Both must work at the same time.
- Star currency dropped by enemies. Stars persist across runs and buy permanent upgrades between missions.
- At least 3 fully distinct maps. Each map has mixed static emplacements and moving enemies, mid-wave set pieces, and one unique big boss at the end.
- Compelling secondary weapons: bombs, missiles, and lasers, each with cooldowns, distinct VFX, and upgrade paths.
- Feel over feature-list. Every shot, explosion, pickup, and boss phase must read clearly and feel expensive.

TECH
- Native local program for the operating system you are running on (detect it first, e.g. Ubuntu Linux). Not a browser game.
- Use a local game library or engine: SDL2/SDL3 (C/C++), pygame (Python), or Godot 4. Check what is already installed, pick the one that best reaches the quality bar (shaders for bloom / heat distortion are a strong reason to favour Godot or SDL + GPU), and state the choice and why in the README. Install any missing dependencies through the system package manager or pip and record the exact commands.
- One command to build and one command to run from a clean checkout (e.g. `make run`, `python3 main.py`, or `godot --path .`).
- Windowed and fullscreen (F11 toggle), resolution-independent scaling.
- 16:9 or 9:16 portrait-friendly layout with a letterboxed playfield if needed. Target 60fps.
- Gamepad (via the library's native controller API, e.g. SDL GameController): left stick / D-pad to move. A = bomb, B = missiles, X or RB = laser. Start = pause. Analog movement with a small deadzone.
- Keyboard: WASD or arrows move. Space unused for fire (auto-fire). Q = bomb, E or F = missiles, R or Shift = laser. Esc pause.
- Persist stars, upgrade levels, unlocked maps, and high scores in a JSON save file under the user data directory (e.g. $XDG_DATA_HOME or ~/.local/share/stellar-revenant/). Write atomically so a crash cannot corrupt the save.
- Pause, mute, and a simple settings panel (volume sliders, invert Y optional, rumble on/off).
- Gamepad rumble on hits, bomb, and boss phase changes when supported.

PLAYER SHIP
- Sleek interceptor with engine trails, afterburner heat, wing lights, and a faint shield shimmer when healthy.
- Auto primary: dual / quad forward cannons. Fire rate and projectile count scale with upgrades. Subtle recoil and muzzle flash.
- Movement: 8-way, snappy with slight inertia. Clamp to playfield. Optional “focus” slower move when holding a modifier (LT / Left Ctrl) for precision.
- Health: visible hull bar + shield layer. First hits eat shield. Invuln frames + flash + rumble on hit. Game over on hull zero.
- Star magnet radius that grows with upgrades so stars curve toward the ship.

SECONDARY WEAPONS (all upgradeable)
1. MEGABOMB — clears most bullets and damages everything on screen. Massive expanding shockwave, white flash, bass drop. Long cooldown. Limited charges per run, refillable via pickups and hangar upgrades.
2. MISSILES — lock or fire in a spread, home weakly on nearest threats. Smoke trails, staggered launches, clustered explosions. Medium cooldown / ammo.
3. LASER — hold or tap for a piercing beam that sweeps or locks forward. Heat haze, beam cores, burn marks on bosses. Overheats or has a short energy bar.

PRIMARY UPGRADES (bought with stars in hangar)
- Main cannon power / fire rate / extra streams
- Hull integrity
- Shield capacity + recharge
- Star magnet range
- Bomb damage + cooldown + max charges
- Missile count / tracking / damage
- Laser width / duration / damage
Each upgrade has 5–8 tiers with clear numeric preview and a “next cost” shown. Costs scale.

CURRENCY & META
- Enemies drop small stars (1) and occasional large stars (5). Bosses dump a shower.
- Stars collected this run + banked stars shown in HUD and hangar.
- Hangar screen between maps: 3D-ish or illustrated ship bay, upgrade grid, map select, brief flavor text.
- Completing a map unlocks the next. Replaying earlier maps is allowed to farm stars.
- Optional medals per map (70% kills, 100% kills, no-hit, all pickups) that grant bonus stars. Implement at least 70% / 100% / no-hit if time is tight.

MAPS (minimum 3, each ~2–4 minutes + boss)
Design each as a authored scroll with scripted spawn waves, not pure random.

MAP 1 — IRON COAST (dusk ocean / ruined harbors)
- Mood: amber sun, rusted platforms, AA batteries, patrol boats, gulls, water reflections.
- Static: shore turrets, bunker guns, mine fields, SAM sites that wake when approached.
- Dynamic: fighter wings, gunships that strafe across, bombers that drop bombs downward, speedboats.
- Set pieces: collapsing crane, missile barrage from offscreen destroyer.
- BOSS: Dreadnought “ORION-KEEL” — multi-deck warship that fills the width. Phases: broadside batteries → rotating laser arrays → exposed core after destroying side turrets. Weak points glow. Intro and death cinematics.

MAP 2 — NEON CANYON (night megacity / canyon of glass)
- Mood: rain, holograms, neon signage, searchlights, wet asphalt reflections.
- Static: rooftop flak, billboard drones that unfold into guns, laser fences.
- Dynamic: drone swarms, tilt-rotor gunships, subway trains that cross the field as moving cover/hazard.
- Set pieces: skyscraper collapse that changes the scroll path, EMP pulse that briefly blinds HUD.
- BOSS: “HELIX SPIRE” — hovering command tower with orbiting shield rings. Phases: ring drones → rotating beam spokes → core exposed when rings destroyed. Telegraphs clearly.

MAP 3 — VOID FORGE (orbital foundry / asteroid foundry)
- Mood: industrial black, molten metal rivers, welding sparks, zero-g debris, solar glare.
- Static: foundry turrets, magnetic rails that yank projectiles, furnace vents that pulse AoE.
- Dynamic: asteroid clusters used as cover by enemies, repair drones that heal elites, heavy walkers.
- Set pieces: gravity shear that tilts bullet patterns, molten flood that forces the player to a lane.
- BOSS: “PROTO-SUN” — spherical forge core with petal armor. Phases: petal guns → orbiting singularity that pulls stars/bullets → full beam garden. Final explosion is the money shot.

ENEMIES
- At least 8 distinct types across maps (grunt fighter, armored gunship, turret, bomber, kamikaze, elite shielded, support healer, mini-boss mid-map).
- Mix of static map objects and mobile units. Static units have wake-up animations and limited aim cones.
- Attack patterns must be readable: wind-up frames, glow, then fire. Bullet colors distinguish danger types (standard, tracking, laser, explosive).
- Elites and bosses have weak points. Destroying parts changes the fight.
- Death: debris, sparks, delayed secondary explosions, star burst. Never a pop-and-vanish.

COMBAT FEEL
- Auto-fire always on. Fire cadence is musical, not noisy spray.
- Hit-stop (2–4 frames) on chunky hits and boss part breaks.
- Screen shake scaled to event size. Never constant.
- Bullet hell density ramps per map but always leaves escape corridors.
- Pickup vacuum: stars, weapon crates (bomb/missile/laser refill), health packs, brief power spikes.
- Combo / chain text for rapid kills (Nice / Great / Superb) with score pop.

UI / HUD
- Minimal, diegetic: hull, shield, star count, secondary cooldowns as icons with sweep timers.
- Boss health bar with named phases.
- Brief mission title card at map start. Victory / defeat screens with stars earned, medals, and “return to hangar”.
- Hangar is beautiful: your ship on a pad, upgrade nodes lighting up as purchased.

AUDIO (generate or synthesize procedural + samples)
- Distinct SFX: cannon ticks, missile whoosh, bomb detonation, laser hum, shield break, star collect chime (layered so 20 stars don’t become noise), UI clicks.
- Per-map music beds that intensify at mid-map and boss. Boss themes must change on phase 2.
- Mix: music ducked slightly on bomb; bass on explosions. Mute toggle.

VISUAL QUALITY BAR
- AAA arcade: high-contrast silhouettes, bloom on engines and explosions, motion blur on fast projectiles, parallax 4+ layers, weather (rain, embers, ash) per map.
- Ship and bosses must look designed, not primitive polygons. If generating sprites, use consistent art direction: dark metal, cyan/amber energy, weathered decals.
- VFX library: muzzle flash, impact sparks, shock rings, debris, heat shimmer, death blooms, star sparkle trails.
- No clip-art UI. Custom HUD frames.

STRUCTURE THE CODE
- Clear modules: input, player, weapons, enemy, spawner/timeline, boss FSM, pickups, upgrades, persist, audio, renderer.
- Data-driven waves (JSON or data files / tables in the chosen language) so maps can be tuned without rewriting systems.
- Object pools for bullets, particles, enemies.
- Debug overlay toggle (F1): hitboxes, spawn IDs, FPS.

PROGRESS TRACKER (build this first, keep it current)
- Before writing game code, break this whole goal into a numbered task list grouped by milestone (setup, core loop, weapons, enemies, each map, each boss, meta/hangar, audio, polish, README).
- Create progress.html in the project root: a single self-contained page (inline CSS + JS, no server, no CDN, opens via file://) that shows every task with its status (todo / in progress / done / cut), a per-milestone progress bar, an overall percent complete, the current task highlighted, and a last-updated timestamp.
- Keep the task data as one inline JS array at the top of the file so updating status is a one-line edit. Add <meta http-equiv="refresh" content="10"> so an open tab stays live.
- Update progress.html every time a task starts or finishes, before moving on. Add newly discovered tasks; mark cut scope as "cut" with a one-line reason rather than deleting it.
- Only mark a task done after it has been run and verified in the actual game, not just written.

DELIVERABLES
1. Playable game from splash → hangar → map 1 → boss → hangar → map 2 → map 3.
2. All three bosses unique and multi-phase.
3. Working gamepad + keyboard, auto-fire primary, three secondaries.
4. Star economy + at least the upgrade list above.
5. README with engine choice, dependencies, build/run commands, and controls.
6. Polish pass: juice, audio, particles, hangar art, title screen.
7. progress.html showing every task complete or explicitly cut.

ACCEPTANCE
A player can finish all 3 maps, buy upgrades with stars, feel the ship get stronger, and say the bosses and explosions look expensive. If something must be cut, cut extra medals and extra ships before cutting bosses, secondaries, or juice.

MULTI-MODEL ORCHESTRATION
I want you to use the three models concurrently to build a game over many hours using a goal prompt. The models are the QWen3.5-.4 model running on ml-server, the qwen3.8-27B model running on ml-server and the qwen36-35B-a3b model running on r730. I want you to create a realtime status webpage locally on ml-server that shows what is planned, what has been worked on, which model has done it, any issues like OOM or running out of context and I want to know of any failures to complete tasks by a model. I would also like a visually stunning graphical representation on that webpage that shows how much work each model has done. All data for the website should be logged to a text based file.

MODEL BENCHMARK (do this first, keep it quick)
- Before allocating any work, run a fast benchmark (a few minutes total) on every available model: the same small coding task (e.g. write and fix a short game-module function against a test), plus tokens/sec, time to first token, usable context length, and whether the output ran correctly.
- Log the results to the text log file and show them on the status webpage.
- Use the benchmark when allocating work: give the hardest, most architectural tasks (renderer, boss FSMs, shaders) to the strongest model, and fast, well-scoped tasks (data tables, wave scripts, UI wiring, asset generation) to the fastest models. Re-balance if a model keeps failing or hitting OOM / context limits.
- Every available model must be allocated work. None may sit idle for the whole run.
- Each model may only have one task assigned at a time. Do not give a model a new task until its current one is finished, failed, or reassigned.

ITERATION LOOPS (minimum 3)
- Complete at least 3 full loops of: plan → build → run and playtest → review against this goal → fix and improve.
- Each loop must end with the game building and running. Record each loop's findings, what changed, and which model did what in the log and on the status webpage.
- Do not stop after loop 3 if deliverables or acceptance criteria are still unmet.
